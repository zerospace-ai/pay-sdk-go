## 1. Глобальная общедоступная информация

Все данные ответов JSON, возвращаемые платформой, следуют этой общей структуре:

| Имя поля | Тип | Пример | Описание |
| :--- | :--- | :--- | :--- |
| `code` | integer | `1` | Глобальный код состояния. `1` означает успех, `0` или `-1` означает сбой |
| `msg` | string | `ok` | Возвращенное текстовое описание |
| `data` | object | `{"OpenId":"PT00001"}` | Возвращаемое конкретное содержимое данных, которое зависит от API |
| `timestamp` | string | `"1725439986754"` | Метка времени UTC (в миллисекундах) |
| `sign` | string | `9e0ccfe3915e...` | Подпись, сгенерированная платформой с использованием ее закрытого ключа RSA для данных ответа |

## 2. Создать нового пользователя (create_user)

### Описание API
Создает нового пользователя платформы. Требуется уникальный идентификатор пользователя, которым является UserOpenId.

### HTTP-запрос
* **URL:** `https://sandbox-api.privatex.io/sdk/user/create`
* **Метод:** `POST`

### Параметры запроса
| Имя параметра | Обязательно | Тип | Описание |
| :--- | :--- | :--- | :--- |
| `OpenId` | Да | string | Рекомендуется использовать стандартный префикс платформы + уникальный идентификатор пользователя для формирования OpenId. |

### Параметры ответа
*(Включает глобальную информацию)*
| Имя параметра | Тип | Описание |
| :--- | :--- | :--- |
| `data.OpenId` | string | Уникальный OpenId пользователя |

### Пример кода (cURL)
```bash
curl --location 'https://sandbox-api.privatex.io/sdk/user/create' \
--header 'key: vratson2i5hjxgkd' \
--header 'sign: 0592dc64d480fb119d1e07ce06011db8' \
--header 'clientSign: xxxxxxxxxxxxxxxxx' \
--header 'Content-Type: application/json' \
--header 'timestamp: 1725076567682' \
--data '{ 
  "OpenId":"PT00001"
}'
```

## 5. Вывод средств пользователя (user_withdraw_by_open_id)

### Описание API
Инициирует операцию вывода средств, переводя средства из пула партнера на указанный пользователем адрес.

> **⚠️ Предупреждение:**
> * Как только транзакция инициирована в сети блокчейн, ее **невозможно отменить или вернуть**. Перед вызовом этого API убедитесь, что выполнены надлежащие проверки контроля рисков.
> * Вы должны убедиться, что в пуле вывода достаточно баланса токена и комиссий за газ (например, ETH/TRX).

### Бизнес-логика
1. Уникальный номер заказа с бизнес-платформы обычно используется в качестве `SafeCheckCode` для предотвращения дублирования выводов.
2. Транзакция сопоставляется с правилами контроля рисков платформы:
   * **Автоматическое одобрение:** Транзакция сразу попадает в цепочку, и `data` вернет хэш транзакции.
   * **Вторичная проверка (`code=2`):** Требует ручной проверки администратором на платформе канала. После проверки статус будет сообщен асинхронно через Webhook.

### HTTP-запрос
* **URL:** `https://sandbox-api.privatex.io/sdk/partner/UserWithdrawByOpenID`
* **Метод:** `POST`

### Параметры запроса
| Имя параметра | Обязательно | Тип | Описание |
| :--- | :--- | :--- | :--- |
| `OpenId` | Да | string | Уникальный OpenId пользователя |
| `TokenId` | Да | string | ID токена (См. приложение)|
| `Amount` | Да | float | Сумма вывода |
| `AddressTo` | Да | string | Целевой адрес вывода |
| `CallBackUrl` | Нет | string | URL-адрес обратного вызова при изменении статуса |
| `SafeCheckCode` | Нет | string | Код проверки безопасности (ID бизнес-заказа) |

### Описание кода состояния ответа
| `code` | Описание |
| :--- | :--- |
| `1` | Транзакция успешно выполнена и отправлена в цепочку, `data` возвращает хэш. |
| `2` | Транзакция отправлена, но сработал контроль рисков платформы, требуется вторичная проверка. |
| `0` или `-1` | Ошибка параметра, недостаточно средств или сбой транзакции. Подробности см. в `msg`. |

### Пример кода (cURL)
```bash
curl --location 'https://sandbox-api.privatex.io/sdk/partner/UserWithdrawByOpenID' \
--header 'key: vratson2i5hjxgkd' \
--header 'sign: 0592dc64d480fb119d1e07ce06011db8' \
--header 'clientSign: xxxxxxxxxxxxxxxxx' \
--header 'Content-Type: application/json' \
--header 'timestamp: 1725076567682' \
--data '{ 
  "OpenId": "PT00001", 
  "TokenId": "4", 
  "Amount": "0.02", 
  "AddressTo": "TQdL5yttJPTx7hJmBhGfo2LcE7AXLPtHSg", 
  "CallBackUrl": "http://xxxxxx/withdraw_callback", 
  "SafeCheckCode": "1000000000000000"
}'
```

## 6. Вторичная проверка ордера на вывод (Webhook)

### Описание обратного вызова
Когда администратор настраивает "URL-адрес обратного вызова для контроля рисков" в бэкенде продавца, платформа будет активно инициировать HTTP-запрос к этому URL-адресу при обработке транзакции вывода, чтобы спросить бизнес-сторону продавца, следует ли разрешить вывод.
**Платформа переведет средства только в том случае, если API продавца вернет `code=0`.**

> **⚠️ Примечание:** Платформа назначит продавцу независимый **Открытый ключ RSA для контроля рисков (`PlatformRiskPubKey`)**. Продавец должен использовать этот открытый ключ для проверки подлинности подписи этого обратного вызова.

### HTTP-запрос, инициируемый платформой
* **Метод:** `POST`
* **URL:** Настроенный продавцом URL-адрес Webhook `/withdrawal/order/check`

### Параметры обратного вызова
| Имя параметра | Обязательно | Тип | Описание |
| :--- | :--- | :--- | :--- |
| `safeCode` | Нет | string | Отправленный продавцом ID заказа на вывод (`SafeCheckCode`) |
| `openId` | Да | string | ID пользователя, осуществляющего вывод |
| `tokenId` | Да | string | ID токена |
| `toAddress` | Да | string | Целевой адрес вывода |
| `amount` | Да | string | Сумма вывода |
| `timestamp` | Да | int | Метка времени в миллисекундах |
| `sign` | Да | string | Подпись, сгенерированная платформой с использованием ее закрытого ключа контроля рисков |

### Ожидаемый ответ от продавца
После обработки API продавца должен вернуть следующий JSON:

| Имя параметра | Тип | Описание |
| :--- | :--- | :--- |
| `code` | int | Результат проверки. `0` означает согласие на разрешение вывода; другие числа означают отклонение. |
| `timestamp` | int | Текущая метка времени в секундах |
| `message` | string | Пользовательское описание |
| `sign` | string | Продавец подписывает данные ответа, используя свой собственный закрытый ключ RSA |

## 7. Уведомление об обратном вызове при пополнении и выводе (Webhook)

### Описание обратного вызова
Платформа отправляет асинхронные уведомления о статусе транзакции токена (успех/неудача вывода средств или зачисление средств пользователю) на бизнес-сторону.

1. **Механизм повторных попыток:** Бизнес-сторона должна ответить кодом возврата `0`, чтобы сообщение считалось успешно полученным. В противном случае платформа будет постоянно повторять попытки отправки в соответствии со стратегией (сначала 50 раз каждые 2 секунды, затем один раз каждые 10 минут).
2. **Переопределение статуса:** Одна транзакция может вызывать несколько уведомлений. Пожалуйста, полагайтесь на последний статус.
3. **Обработка ошибок:** Если статус обратного вызова вывода `status = -1`, после того как администратор повторно отправит транзакцию в бэкенде, система снова отправит новое уведомление о статусе.

### HTTP-запрос, инициируемый платформой
* **Метод:** `POST`
* **URL:** URL-адрес обратного вызова, предоставленный продавцом поставщику услуг.

### Параметры обратного вызова
| Имя параметра | Обязательно | Тип | Описание |
| :--- | :--- | :--- | :--- |
| `type` | Да | int | Тип бизнеса: `1` для пополнения; `2` для вывода. |
| `status` | Да | int | Статус транзакции:<br/> `1`: Успешно в цепочке, можно запросить через хэш.<br/> `-1`: Ошибка в цепочке, может быть обработана в бэкенде.<br/> `2`: Сработал контроль рисков, требуется ручная проверка в бэкенде администратора.<br/> `-2`: Заявка на вывод отклонена API контроля рисков продавца. |
| `openid` | Да | string | Уникальный ID пользователя канала |
| `totalvalue` | Да | string | Эквивалентная стоимость USDT, рассчитанная на основе рыночной цены на момент транзакции |
| `hash` | Да | string | Хэш транзакции в цепочке |
| `confirm` | Да | int | Количество подтверждений в цепочке |
| `from` | Да | string | Адрес инициатора транзакции |
| `to` | Да | string | Адрес получения транзакции |
| `amount` | Да | string | Сумма транзакции |
| `chainid` | Да | string | ID цепочки |
| `tokenid` | Да | string | ID токена |
| `tokenaddress` | Да | string | Адрес смарт-контракта |
| `safecode` | Нет | string | Код проверки безопасности ордера на вывод (OrderID) |
| `createdtime` | Да | string | Время создания транзакции |
| `timestamp` | Да | string | Метка времени отправки |

### Ожидаемый ответ от продавца
При успешном получении верните тело ответа JSON, содержащее `{"code": 0}`.

## 8. Создание кассового ордера (new_order)

### Описание API
Этот интерфейс используется мерчантами для инициации запросов на оплату или пополнение. Система вернет адрес оплаты (URL кассы), и пользователь сможет перейти по этому адресу для завершения процесса оплаты.

### HTTP-запрос
* **URL:** `https://vapi.dogpay.ai/sdk/api/v2/exchange/cashier/newOrder`
* **Метод:** `POST`

### Параметры запроса
| Имя параметра | Обязательно | Тип | Описание |
| :--- | :--- | :--- | :--- |
| `outOrderNo` | Да | string | Уникальный ID заказа на стороне мерчанта (используется для предотвращения повторной отправки и для сверки) |
| `tokenId` | Да | integer | ID токена |
| `quantity` | Да | decimal | Сумма/количество заказа |
| `notifyUrl` | Нет | string | Адрес асинхронного уведомления после успешной оплаты |

### Параметры ответа
*(Включает глобальную информацию)*
| Имя параметра | Тип | Описание |
| :--- | :--- | :--- |
| `data.orderNo` | string | Уникальный ID заказа, сгенерированный платформой |
| `data.outOrderNo` | string | Оригинальный ID заказа, переданный мерчантом |
| `data.cashierUrl` | string | **Основное поле**: Адрес страницы кассы. Мерчанты должны направлять пользователей по этой ссылке для оплаты. |

### Пример кода (cURL)
```bash
curl --location 'https://vapi.dogpay.ai/sdk/api/v2/exchange/cashier/newOrder' \
--header 'key: your_api_key' \
--header 'sign: your_md5_sign' \
--header 'clientSign: your_rsa_sign' \
--header 'Content-Type: application/json' \
--header 'timestamp: 1770606706659' \
--data '{  
  "outOrderNo": "1234623",   
  "tokenId": 6,   
  "quantity": 0.01,   
  "notifyUrl": "https://your-domain.com/callback"   
}'
```

## 9. Колбэк об успешной оплате кассового ордера (Webhook)

### Описание колбэка
После того как пользователь завершит оплату на странице кассы, DogPay отправит асинхронное уведомление на `notifyUrl`, предоставленный мерчантом.

### HTTP-запрос, инициируемый платформой
* **Метод:** `POST`
* **URL:** `notifyUrl`, предоставленный мерчантом

### Параметры колбэка
| Имя параметра | Тип | Описание |
| :--- | :--- | :--- |
| `orderId` | string | Системный ID заказа платформы |
| `outOrderId` | string | Оригинальный ID заказа мерчанта |
| `orderStatus` | string | **Статус заказа**: 2 обычно означает успешную оплату |
| `tokenId` | string | ID токена |
| `quantityPaid` | string | **Фактическое количество, оплаченное пользователем** |
| `sign` | string | **Подпись данных** (используется для проверки мерчантом для предотвращения поддельных колбэков) |

### Ожидаемый ответ от мерчанта
При успешном получении верните следующий JSON:
```json
{
  "code": "1",
  "message": "success"
}
```

## 10. Запрос баланса кошелька (wallet_balance)

### Описание API
Запрашивает баланс токенов или монет для указанного адреса кошелька в определенной сети блокчейна.

### HTTP-запрос
* **URL:** `https://sandbox-api.privatex.io/sdk/wallet/balance`
* **Метод:** `POST`

### Параметры запроса
| Имя параметра | Обязательно | Тип | Описание |
| :--- | :--- | :--- | :--- |
| `address` | Да | string | Адрес кошелька |
| `contractAddress` | Да | string | Адрес смарт-контракта или символ токена (например, `"XRP"`, `"USDT"`) |
| `chainId` | Да | integer | ID блокчейн-сети (например, `5` для XRP, `1` для Ethereum, `56` для BNB Chain) |

### Параметры ответа
*(Включает глобальную информацию)*
| Имя параметра | Тип | Описание |
| :--- | :--- | :--- |
| `code` | integer | Глобальный код состояния (`1` означает успех) |
| `msg` | string | Описание состояния |
| `data` | string | Баланс токенов / монет (в минимальных неделимых единицах) |
| `timestamp` | string | Метка времени ответа (в миллисекундах) |
| `sign` | string | Подпись данных платформы |

### Пример кода (cURL)
```bash
curl --location --request POST 'https://sandbox-api.privatex.io/sdk/wallet/balance' \
--header 'key: your_api_key' \
--header 'sign: your_md5_sign' \
--header 'Content-Type: application/json' \
--header 'timestamp: 1725076567682' \
--data-raw '{
  "address":"rXXXXXXXXXXXXXXXXXXXXXXXXXXXX",
  "contractAddress":"XRP",
  "chainId":5
}'
```

### Пример ответа
```json
{
  "sign" : "",
  "timestamp" : "1725432397796",
  "data" : "1979984",
  "msg" : "ok",
  "code" : 1
}
```
